# ВСТУП

## Актуальність теми

Проблема харчових відходів залишається актуальним інженерним викликом для сектору HoReCa та роздрібної торгівлі: галузеві оцінки фіксують втрати до 6% обороту через списання товарів з обмеженим терміном придатності. Наявні цифрові рішення для перерозподілу надлишкової продукції (Too Good To Go, GoodMeal) орієнтовані виключно на бік споживача та не усувають операційного бар'єра з боку постачальника — ручне фотографування, опис і внесення кожної одиниці залишків у систему адміністративним персоналом закладу в умовах обмеженого часу наприкінці зміни. Це формує supply-side friction, що обмежує масштабованість подібних платформ.

Інженерна складність проєкту визначається необхідністю забезпечити низьку затримку (latency) обробки запитів мобільного застосунку персоналу закладу за умови асинхронної, потенційно повільної операції розпізнавання зображень через зовнішній Vision API, а також відмовостійкість (fault tolerance) системи до пікових навантажень наприкінці робочих змін закладів-постачальників. Розв'язання цих задач вимагає архітектурного відокремлення синхронного шляху обробки HTTP-запитів від асинхронної обробки задач комп'ютерного зору за допомогою черги повідомлень, кешування агрегованих аналітичних метрик та проєктування контрактної мікросервісної взаємодії через REST API з незалежним B2C-модулем.

## Об'єкт дослідження

Процес автоматизованого формування та обробки торгових пропозицій (лотів) на основі розпізнавання товарних залишків закладів харчування засобами комп'ютерного зору, включно з асинхронною обробкою зображень, агрегацією фінансово-облікової аналітики та міжсервісною передачею даних у розподіленій архітектурі перерозподілу продукції.

## Предмет дослідження

Методи та моделі розпізнавання об'єктів на зображеннях (комп'ютерного зору) для автоматизованого формування торгових лотів; архітектурні патерни побудови мікросервісної B2B-інформаційної системи (N-Tier, Producer-Consumer); методи асинхронної обробки задач через чергу повідомлень (BullMQ/Redis); підходи до кешування аналітичних агрегатів і контрактної інтеграції через REST API.

## Мета роботи

Проєктування та розробка інформаційної системи автоматизації B2B-продажів закладів харчування з інтегрованим модулем розпізнавання інвентарю на основі комп'ютерного зору, що реалізує процес автоматизованого формування торгових лотів і фінансової аналітики, спрямовані на скорочення трудовитрат персоналу закладів на облік залишків та підвищення відмовостійкості й масштабованості платформи перерозподілу товарів.

## Завдання проєкту

1. Проаналізувати наявні B2B-рішення для перерозподілу товарів з обмеженим терміном придатності та підходи до автоматизованого розпізнавання інвентарю за ДСТУ.
2. Обґрунтувати вибір технологічного стеку (Node.js, NestJS, PostgreSQL, BullMQ, Redis) для реалізації мікросервісної архітектури B2B-модуля.
3. Спроєктувати архітектуру системи у нотації UML/C4 Model, включно зі структурою бази даних та контрактом взаємодії з B2C-модулем через REST API.
4. Алгоритмізувати критичні вузли системи: асинхронну обробку зображень через чергу задач та формування смарт-бандлів на основі розпізнаних позицій.
5. Спроєктувати інтерфейс мобільного застосунку для адміністраторів і касирів та схему розгортання системи (Docker, CI/CD).
6. Провести інструментальний аудит розробленого коду шляхом модульного та інтеграційного тестування (Jest, Supertest).
7. Здійснити науково-практичну апробацію отриманих результатів шляхом підготовки статті/доповіді за результатами дослідження.
