# Специфікація вимог до програмного забезпечення (SRS)

Інформаційна система автоматизації B2B-продажів та розпізнавання інвентарю закладів харчування засобами комп'ютерного зору. Структура документа відповідає ISO/IEC/IEEE 29148. Джерело вимог: підрозділи 1.4 і 1.5 [Розділу 1](./1_analysis.md). Архітектурну реалізацію вимог описано в [Розділі 2](./2_design.md).

Модальне дієслово «повинна» (або «повинен») позначає обов'язкову вимогу. Кожна вимога має унікальний ідентифікатор і верифікується способом, наведеним у розділі 4.

## 1. System Context

Система є B2B-модулем платформи перерозподілу товарів з обмеженим терміном придатності. Вона складається з мобільного застосунку для персоналу закладу (React Native) та серверної частини (NestJS, PostgreSQL, Redis, BullMQ). Система виконується окремо від B2C-модуля та взаємодіє з ним лише через REST API за контрактом OpenAPI 3.1 ([`contracts/b2c-contract.yaml`](../contracts/b2c-contract.yaml)).

Межі системи (Scope):

- у межах системи: формування лотів із фотографій, каталог меню, рольова модель персоналу, підтвердження видачі за QR-кодом, фінансова аналітика закладу, REST API для B2C-модуля;
- поза межами системи: застосунок покупця, оплата, динамічне ціноутворення, бронювання, інтеграція з POS-системами.

Зовнішнє середовище:

| Учасник | Тип | Взаємодія |
| --- | --- | --- |
| Адміністратор закладу | Користувач | Керує меню, лотами, обліковими записами касирів; переглядає аналітику |
| Касир | Користувач | Публікує лоти, скануює QR-код і підтверджує видачу |
| Покупець | Зовнішній користувач | Оформлює замовлення в B2C-модулі, пред'являє QR-код |
| B2C-модуль | Зовнішня система | Забирає фід лотів, надсилає підтвердження покупок, запитує QR-код (REST API, HTTPS) |
| Vision API (OpenAI або Google Gemini) | Зовнішній сервіс | Повертає перелік розпізнаних позицій для зображення (HTTPS) |

Припущення та обмеження:

- розгортання виконується на одному вузлі (Docker, docker-compose); багаторегіональне розгортання та реплікація СУБД не передбачені;
- B2C-модуль виконується незалежно; зміни контракту узгоджуються окремо;
- зовнішні вимоги: Закон України «Про захист персональних даних», Регламент (ЄС) 2016/679 (GDPR), OWASP API Security Top 10 (2023).

## 3. Non-Functional Requirements

Тестове середовище для вимог продуктивності (далі — Стенд): один екземпляр API, 2 vCPU, 4 ГБ RAM; PostgreSQL і Redis у docker-compose на тому самому вузлі; навантаження тривалістю не менше 5 хв; допустима частка помилок (HTTP 5xx і тайм-аути) — менше 1 %; кеш Redis прогрітий.

## 5. Glossary

| Термін | Визначення |
| --- | --- |
| Лот | Торгова пропозиція закладу: товар або смарт-бандл із ціною, кількістю та інтервалом видачі |
| Смарт-бандл | Комбінована пропозиція з двох або трьох розпізнаних позицій різних категорій |
| Producer–Consumer | Шаблон, у якому API (Producer) ставить завдання в чергу BullMQ, а окремі обробники (Consumer) виконують їх асинхронно |
| p95 Latency | Значення часу відповіді, яке не перевищують 95 % запитів вибірки |
| Idempotency | Властивість операції, за якої повторне виконання з тими самими вхідними даними не змінює результату після першого виконання |
| Dead-Letter Queue | Черга, до якої потрапляють завдання після вичерпання повторних спроб обробки |
| JWT | Підписаний токен у форматі JSON Web Token (RFC 7519), що використовується для автентифікації запитів |
